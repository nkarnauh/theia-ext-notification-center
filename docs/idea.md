# Notification Center

## Задача
Реализовать систему уведомлений: backend-сервис публикует типизированные уведомления, frontend отображает всплывающие сообщения/toast и ведет историю уведомлений в боковой панели.
## Функциональные требования
### Backend – NotificationService (Theia backend)
1.	Типизированный RPC-интерфейс. Структура уведомления:
{ id: string, severity: ‘info’ | ‘warning’ | ‘error’, title: string, message: string, actions?: { label: string, id: string}[]}.
2.	Push-событие. При вызове push() сервис немедленно отправляет событие на frontend через Theia event bus.
3.	Метод getHistory(): Promise<Notification[]>. Возвращает последние 100 уведомлений в хронологическом порядке. Хранит in-memory.
4.	При превышении лимита в 100 записей старые вытесняются.
### Frontend – Notification Panel
5.	При получении события onNotification показывает уведомление/toast (MessageService или кастомный overlay). Уведомления/toast автоматически скрывается через 5 секунд для info/warning. Error – остается до явного закрытия.
Кнопки из actions[] отображаются в уведомлении/toast; клик отправляет событие actionInvoked(…) на backend.
6.	TreeWidget или ReactWidget в боковой панели со списком всех уведомлений. Иконка severity слева от каждой записи (info / waning / error). Метка времени а формате HH:MM:SS. Клик на запись с actions[] разворачивает кнопки действий.
7.	Фильтрация по severiry (три чекбокса в тулбаре)
8.	Кнопка «Очистить все» в тулбаре.
## Нефункциональные требования
1.	Типизированный RPC протокол в common/-пакете – общий интерфейс для frontend и backend.
2.	Подписки на события корректно освобождаются.
## Будет плюсом:
1.	Тесты для backend.
2.	Сохранение истории уведомлений при перезапуске
3.	Группировка уведомлений по дате (Сегодня/Вчера/Раннее)
4.	Анимация появления/исчезновения уведомлений.
